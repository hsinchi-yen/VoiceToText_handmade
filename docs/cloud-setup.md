# 服務與預設組態

v2c 預設**全部使用地端模型**：語音辨識用你電腦上的 Breeze-ASR-25／SenseVoice，潤飾與中翻英用 LM Studio。不需要任何 API 金鑰就能使用。

如果你想讓辨識更快、潤飾更好，或電腦沒有足夠的顯示卡，可以把某些用途交給**服務**（雲端或區網的伺服器）。這是**選用**的。

選單上的「**服務**」頁（0.1.x 叫「雲端服務」；Android 版 App 畫面裡的對應區塊叫「雲端服務」）管理所有服務。有兩種設定方式：

| 你的情況 | 做法 |
|----------|------|
| 公司區網（TN／RD）有現成的語音辨識與文字模型伺服器 | **最快**：「首頁 → 套用預設組態」，見下一節 |
| 要用自己的伺服器，或 Gemini、OpenAI、Claude | 「服務 → 新增服務」精靈，見〈新增服務精靈的 7 個步驟〉 |

> **費用與隱私**
> 雲端服務會依用量向你收費，錄音或文字會上傳到該服務。
> 只有你交給服務的用途會送出去；沒交給服務的仍然在你的電腦上處理。

## 預設組態（一鍵設好區網服務）

預設組態是「一整組服務＋用途分配」的設定包。套用一次，就同時加好語音辨識、潤飾、中翻英要用的服務，並把三個用途分配好。

### 內建的兩組：TN 與 RD

| | TN | RD |
|---|----|----|
| 伺服器位址 | `10.20.30.23` | `10.88.95.2` |
| 語音辨識（二選一） | TEA-ASR（`:8001`）或 Breeze-ASR（`:8002`） | 同左 |
| 潤飾、中翻英 | Qwen3.8 27B（`:8000`） | 同左 |
| 需要金鑰 | TEA-ASR 與 Breeze-ASR（都已內建預設金鑰） | TEA-ASR 與 Breeze-ASR（都已內建預設金鑰） |

- Breeze-ASR 的語音辨識逾時已預設為 8000 毫秒（Breeze 較慢）。
- 文字模型的名稱會自動偵測：套用前 v2c 會向伺服器查模型清單，剛好只有一個模型就用它，否則用預設組態內寫的名稱。預覽畫面會標示「自動偵測」或「預設值」。
- 只有在能連到這些位址的網路（公司區網或 VPN）才用得到。

### 套用步驟

1. 「首頁 → 套用預設組態」（首頁的「預設組態」卡片，上面會顯示目前用的是「TN 區網服務」、「RD 區網服務」、「全部地端」，或「自訂」）。
2. 選 **TN 區網服務** 或 **RD 區網服務**。
3. 在「語音辨識使用」選 **TN TEA-ASR** 或 **TN Breeze-ASR**（RD 則是 RD TEA-ASR／RD Breeze-ASR）。兩者都會出現「API 金鑰」欄，提示「已內建預設金鑰，可不填」：**不用貼金鑰**，套用時會自動把內建的區網共用金鑰存進系統金鑰庫（TEA-ASR 與 Breeze-ASR 任選哪個都會存，之後改選 Breeze 也不用再貼）。要換成別的金鑰才在欄位輸入；你輸入的優先，其次是已儲存且網址沒變的舊金鑰，最後才是內建預設金鑰。
4. 按「**套用**」。設定立刻生效，不用重新啟動。
5. 套用後 v2c 會自動對每個服務做連線測試，列出「連線成功（xx ms）」或失敗原因。

簡短版：「首頁 → 套用預設組態 → TN → 選 TN TEA-ASR → 套用」，然後按住右 Ctrl 說話。

套用完成後若某個服務「測試失敗」（例如網路不通），設定仍然已經套用；請確認你連得到伺服器位址（公司區網或 VPN），或到「服務」頁按該服務的「測試連線」重試。

### 切換 TN 與 RD

直接再套用另一組即可。**兩組服務與各自的金鑰都會保留**（「服務」頁會把它們分成 TN／RD 兩組）；只有語音辨識、潤飾、中翻英「現在交給誰」會改成你剛套用的那一組。你自己新增的服務完全不會被動到。

想用自己的預設組態檔？按「從檔案載入」，格式與錯誤訊息見文末〈附錄：自訂預設組態檔與錯誤訊息〉。

### 想回到沒有預設組態

到「服務」頁把不要的服務「移除」，或系統列圖示右鍵 →「全部改用地端」。

## 新增服務精靈的 7 個步驟

打開 v2c 主視窗 → 選單「服務」→「新增服務」。

<!-- 圖：服務頁與「新增服務」按鈕 -->

### 1. 選擇服務

點選 Gemini、OpenAI、Claude 或「自訂相容端點」。每個選項下方會寫出它能做的用途。

### 2. 取得金鑰

精靈會列出取得金鑰的步驟，並提供「用瀏覽器開啟官方金鑰頁面」按鈕。各家的做法見下方〈各家取得金鑰的方法〉。

自訂相容端點則在這一步填入**端點網址**（base_url），例如 `http://192.168.1.20:1234/v1`，也可以填**名稱（選填）**，見下方〈替自訂相容端點取名〉。

### 3. 貼上金鑰

把金鑰貼進欄位。金鑰會存進 **Windows 認證管理員**（不會寫進設定檔），畫面上只顯示**末 4 碼**。

自訂相容端點若不需要金鑰，留空即可。

### 4. 選擇模型

精靈會預先填好建議的模型。若服務提供模型清單，欄位會出現下拉選單讓你挑；也可以直接輸入模型名稱。

- 語音辨識模型：Claude 沒有這一欄。
- 語音辨識逾時（毫秒，選填）：見下方〈語音辨識逾時〉。
- 文字模型：用於潤飾與中翻英。

#### 語音辨識逾時

每個做語音辨識的服務（Gemini、OpenAI，以及填了語音辨識模型的自訂相容端點）可以各自設定「語音辨識逾時」：一句話送出後，最多等這個服務多久；超過就算逾時，有開「雲端失敗時退回地端」時改用地端辨識。

- 留空：使用預設值，也就是設定檔 `[timeouts] asr_cloud_ms`（欄位中的灰字「預設 5000」就是目前的值）。
- 填整數毫秒，範圍 1000～60000。超出範圍或不是整數，精靈會提示，不會儲存。
- 欄位下方的快選按鈕：

  | 按鈕 | 填入 | 說明 |
  |------|------|------|
  | Breeze-ASR-25 建議 8000 | 8000 | 區網 Breeze-ASR-25 伺服器實測每句約 5.5～6.3 秒（連 2 秒的短句也要 5.5 秒），預設 5000 會逾時 |
  | TEA-ASR 建議 8000 | 8000 | 暫定值，之後依實測調整 |
  | 用預設 | 清空 | 改回使用 `[timeouts] asr_cloud_ms` |

- 語音辨識模型名稱含 `breeze` 或 `tea`（不分大小寫）而逾時欄位空白時，旁邊會顯示建議值提示（不會自動填入）。
- 只影響這個服務：其他服務仍用預設值。第 5 步「測試連線」與實際說話都用這個值。
- 設定檔中是 `[[cloud]]` 底下的 `asr_timeout_ms = 8000`；清空後儲存，這一行會被移除。

### 5. 測試連線

按「開始測試」。語音辨識會送出一段內建的 3 秒測試音檔（不是你的聲音），文字模型會送出一句測試文字。結果會顯示每一項是否通過與延遲（毫秒）。

失敗時會用白話說明原因，對照下方〈疑難排解〉。

<!-- 圖：測試連線結果 -->

### 6. 指定用途

勾選要交給這個服務的用途：語音辨識／潤飾／中翻英。**沒勾的維持地端**。測試沒通過的用途無法勾選。

按「儲存」。

### 7. 完成

設定立刻寫入。之後想全部切回地端，見〈切回地端〉。

## 各家取得金鑰的方法

以下網址於 2026 年 11 月確認。

### Google Gemini

1. 開啟 Google AI Studio 的金鑰頁面：<https://aistudio.google.com/apikey>，用 Google 帳號登入。
2. 按「Create API key」（如果沒看到你的 Google Cloud 專案，先在 Dashboard 的 Projects 匯入）。
3. 複製金鑰（通常以 `AIza` 開頭），貼到精靈第 3 步。

Gemini 有免費額度，超過後依用量計費；免費方案的資料可能被用於改善服務，在意的話請改用付費方案。

### OpenAI

1. 開啟 <https://platform.openai.com/api-keys> 並登入。OpenAI API 和 ChatGPT 訂閱是**分開計費**的。
2. 先到 Billing（<https://platform.openai.com/account/billing/overview>）儲值，否則金鑰呼叫會失敗（顯示「額度不足或請求太頻繁」）。
3. 按「Create new secret key」，複製金鑰（以 `sk-` 開頭，**只會顯示一次**）。

### Anthropic Claude

1. 開啟 Claude Console 的金鑰頁面：<https://platform.claude.com/settings/keys> 並登入。
2. 先在 Billing（<https://platform.claude.com/settings/billing>）儲值。
3. 按「Create Key」，複製金鑰（以 `sk-ant-` 開頭，**只會顯示一次**）。

Claude 只能用於潤飾與中翻英；語音辨識請維持地端或交給另一個服務。

### 自訂相容端點（區網伺服器、別台電腦的 LM Studio）

**一個端點（網址）＝一個服務。** 精靈第 2 步要選「這個端點提供什麼」：

| 選項 | 伺服器要提供 | 例子 |
|------|--------------|------|
| 文字模型（潤飾、中翻英） | `/v1/chat/completions` | llama.cpp、Ollama、vLLM、LM Studio |
| 語音辨識 | `/v1/audio/transcriptions` | whisper.cpp 的 whisper-server、Breeze-ASR 服務 |
| 兩者都有 | 同一個網址兩種都有 | — |

選了之後，第 4 步只會出現需要填的模型欄位，第 6 步也會預先勾好對應的用途。

#### 例子：同一台伺服器，修字和語音辨識在不同連接埠

伺服器 `192.168.1.50` 的 `:8000/v1` 是文字模型、`:8002/v1` 是語音辨識：

1. 「服務 → 新增服務」→「自訂相容端點」。
2. 端點網址 `http://192.168.1.50:8000/v1`，選「**文字模型**」→ 下一步。
3. 貼上金鑰（伺服器不需要就留空）→ 下一步。
4. 文字模型：從下拉清單選（或照伺服器上的名稱輸入）→ 下一步。
5. 測試連線 → 通過後下一步。
6. 勾「潤飾」「中翻英」→ 儲存。
7. 在「完成」頁按「**再新增一個端點（語音辨識）**」：網址會先帶入 `:8000/v1`，把連接埠改成 `:8002/v1`，選項已經是「語音辨識」。
8. 再走一次第 3～6 步：貼金鑰、語音辨識模型（例如 `breeze-asr-25`）、測試、勾「語音辨識」→ 儲存。

完成後，「服務」頁的「**各用途由誰處理**」會列出：語音辨識 → `:8002/v1`、潤飾 → `:8000/v1`、中翻英 → `:8000/v1`。兩個服務的金鑰各自保存。

注意：

- 同一個用途只能交給一個服務；新服務勾了某個用途，原本負責的服務就不再處理它。
- 自架伺服器的語音辨識較慢時，測試可能因逾時失敗：在第 4 步填這個服務的「語音辨識逾時」（Breeze-ASR-25 按「Breeze-ASR-25 建議 8000」），見上方〈語音辨識逾時〉。文字模型較慢時，在 `%APPDATA%\v2c\config.toml` 放寬 `[timeouts] llm_cloud_ms` 與 `[polish] timeout_ms`，然後重新啟動 v2c（見 [lan-server-guide.md](lan-server-guide.md) 第 6.2 節）。
- 會先「思考」再回答的文字模型（例如預設開啟思考的 Qwen3 系列）常常回答被截斷而失敗；請在伺服器端關閉思考（llama.cpp：`--chat-template-kwargs "{\"enable_thinking\":false}"`）。

#### 別台電腦的 LM Studio

1. 在那台電腦的 LM Studio「Developer」頁啟動伺服器，並在伺服器設定開啟「Serve on Local Network」。
2. 端點網址填 `http://那台電腦的IP:1234/v1`（要包含 `/v1`），選「文字模型」。
3. LM Studio 預設不需要金鑰，留空即可。
4. 模型名稱填該伺服器上的模型 ID。LM Studio 只提供文字模型，不能做語音辨識。

官方服務（Gemini／OpenAI／Claude）的網址必須是 `https://`；`http://` 只允許自訂相容端點或本機（localhost）。

## 替自訂相容端點取名

自訂相容端點可以取一個好認的名稱，例如「區網 Qwen」「辦公室語音辨識」。服務清單、「各用途由誰處理」、設定頁與首頁的用途選單都會顯示這個名稱。

- **新增時取名**：精靈第 2 步、端點網址下方的「名稱（選填）」。欄位中的灰字就是沒填時會顯示的代號（`custom`、`custom-2`…）。
- **改名**：服務清單按該服務的「重新命名」（和「修改」是同一個流程，從第 2 步開始），改好名稱後照常走完測試並儲存。
- **取消名稱**：把名稱清空後儲存，畫面就改回顯示代號。

規則：

- 最多 32 個字（中文一個字算一個），頭尾的空白會自動去掉。
- 不能和其他服務的名稱或代號重複（不分大小寫），例如已經有 `custom-2` 時，其他服務不能取名為「Custom-2」。之後新增的端點也會自動跳過已被當成名稱的代號。
- 「local」是保留字（代表地端），不能當名稱。
- 只有自訂相容端點可以取名；Gemini、OpenAI、Claude 直接顯示服務名稱。
- 改名**不會**改變代號：原本交給這個服務的用途、儲存的金鑰都不受影響。設定檔中是 `[[cloud]]` 底下的 `name = "區網 Qwen"`，`id` 仍是 `custom-N`。

## 管理已加入的服務

「服務」頁會把服務依 TN／RD／其他分組，每個服務一張卡片，列出：用途、模型、金鑰末 4 碼；有自訂語音辨識逾時的服務會多一行「辨識逾時 8000 ms」（要改就按「修改」，在第 4 步調整）。

- **測試連線**：用目前設定重新測試。
- **重新命名**（只有自訂相容端點）：見〈替自訂相容端點取名〉。
- **修改**：官方服務（Gemini／OpenAI／Claude）從第 3 步開始，可改金鑰、模型、用途；自訂相容端點從第 2 步開始，可以改端點網址。金鑰欄留空就沿用已儲存的金鑰，但**改了端點網址就必須重新貼上金鑰**（自訂端點若不需要金鑰可留空，舊金鑰會被刪除），避免舊金鑰被送到新的網址。
- **移除**：刪除服務與 Windows 認證管理員裡的金鑰，原本交給它的用途自動改回地端。若畫面提示金鑰沒能刪除，v2c 已不會再使用它，可以自行到認證管理員刪除。

## 切回地端

- **一鍵全部切回**：在系統列的 v2c 圖示按右鍵 →「全部改用地端」，立即生效。服務與金鑰會保留，之後可在「修改」重新勾選用途。
- **只停用某個用途**：「修改」→ 第 6 步取消勾選。
- **完全移除**：「移除」。

另外，設定 `cloud_fallback_to_local = true`（預設）時，雲端呼叫失敗會自動改用地端。

## 疑難排解（依畫面上的訊息）

| 訊息 | 原因與處理 |
|------|-----------|
| 金鑰錯誤（或這把金鑰沒有權限） | 金鑰貼錯、多貼了空白、已被撤銷，或專案沒有權限。回到第 3 步重新貼上；必要時到官方頁面重新建立金鑰。 |
| 額度不足或請求太頻繁 | 帳戶沒有儲值、額度用完，或短時間內請求太多。到該服務的 Billing 頁確認，或稍後再試。 |
| 網路不通（連不到這個服務） | 電腦沒有網路、公司防火牆擋住，或自訂端點的電腦沒開機、LM Studio 伺服器沒啟動、IP 填錯。 |
| 這個端點不支援語音辨識 | 自訂端點沒有 `/audio/transcriptions`（例如 LM Studio）。語音辨識維持地端，只把潤飾／中翻英交給它。 |
| 這個端點不支援文字模型（請確認模型名稱） | 端點沒有 `/chat/completions`，或網址少了 `/v1`。 |
| 伺服器錯誤，請稍後再試 | 服務暫時故障，稍後再試。 |
| 服務回應無法辨認（請確認網址與模型名稱） | 模型名稱打錯或該模型不存在、網址指到別的服務。回第 4 步改用建議模型或下拉清單中的模型。 |
| 逾時：服務回應太慢 | 網路慢或服務忙碌。語音辨識：按「修改」在第 4 步放寬這個服務的「語音辨識逾時」（見〈語音辨識逾時〉）。文字模型：在 `config.toml` 的 `[timeouts]` 調整 `llm_cloud_ms`。 |
| 這個服務沒有提供模型清單（不影響使用） | 自訂端點沒有 `/models`，請自行輸入模型名稱。 |
| 端點網址不正確：官方服務必須是 https:// 開頭 | 自訂的官方服務網址必須用 https。 |
| 無法存取 Windows 認證管理員（金鑰庫） | 重新啟動 v2c；若仍失敗，確認 Windows 帳戶可以使用「認證管理員」。 |
| 設定檔 config.toml 格式有誤，請先修正 | 你手動改過的 `%APPDATA%\v2c\config.toml` 有語法錯誤。v2c 不會覆寫它；修正後再試。 |

## 匯出與匯入設定

換電腦、或想把設好的服務分享給同事時，可以把設定存成一個檔案，再在另一台匯入。入口在「**設定**」頁最下面（「重新執行初次設定」上方）：「匯出設定」與「匯入設定」。Windows 與 Linux 的畫面和檔案格式相同。

### 匯出

1. 按「匯出設定」，選擇存檔位置（預設檔名 `v2c-config-年月日.toml`）。
2. 檔案內容：全部雲端／區網服務、各用途由誰處理、詞庫。熱鍵、麥克風、顯示卡等其他設定不包含。
3. **檔案不含金鑰，但含詞庫，分享前請確認。** 檔案只列出哪些服務需要金鑰，匯入的人要自己貼上。
4. 如果有服務不符合檔案格式而沒有匯出，或某個用途原本指向它而改成本機，匯出後畫面會告訴你。

### 匯入

1. 按「匯入設定」，選一個 `.toml` 檔（自己匯出的，或照 [組態檔說明](config-file.md) 手寫的都可以）。
2. 先看預覽，這時還沒有寫入任何東西：
   - 每個服務是「新增」、「更新」還是「不變」；
   - 各用途（語音辨識、潤飾、中翻英）會改成由誰處理；
   - 詞庫會新增幾個詞（重複的略過）；
   - 檔案裡不會使用的部分（例如整份貼來的 `[hotkey]`）；
   - 需要金鑰的服務，可以在這裡直接貼上；留空表示沿用已存的金鑰，或稍後到「服務」頁補。
3. 按「套用」才會寫入。匯入是**合併**：只新增或更新檔案裡有的服務，其他服務和它們的金鑰不動。
4. 如果某個服務的網址（或種類）和現在的不同，它原本的金鑰會被刪除，不會送到新的主機；請在預覽裡貼上新金鑰。
5. 任何一步失敗（例如設定檔寫不進去），設定、詞庫與金鑰都會維持匯入前的樣子。檔案有問題時整份拒絕，並指出行號與原因。

「套用預設組態」→「從檔案載入」現在也走同一個預覽畫面。

### Linux 的檔案對話框

Linux 版的檔案對話框是 v2c 行程內的 GTK3 對話框，不經過 xdg-desktop-portal（除非設定環境變數 `GTK_USE_PORTAL=1`，或在 Flatpak 內執行）。GNOME Wayland 上應該能開，但尚未實機驗證，驗收時請特別用 **AppImage** 版本測試（`.deb` 版另外確認一次也可以）。如果對話框打不開，請回報，我們會改用 portal 版本。

## 金鑰存在哪裡

- 金鑰存在 Windows 認證管理員（控制台 → 認證管理員 → Windows 認證），項目名稱包含服務代號與 `v2c`（例如 `gemini.v2c`）。
- `config.toml` 只記錄服務種類、網址、模型名稱與用途，不含金鑰。內建預設組態檔（TN、RD）則附有區網 TEA-ASR／Breeze-ASR 伺服器的共用預設金鑰（2026-11-13 起 TEA 也附上：伺服器 `:8001` 同樣要求金鑰），套用時才存進金鑰庫，不會寫進 `config.toml`。
- v2c 的紀錄檔不會寫入金鑰、辨識結果或潤飾後的文字。

## 附錄：自訂預設組態檔與錯誤訊息

### 從檔案載入自訂預設組態

「套用預設組態」第一個畫面按「**從檔案載入**」，選一個 `.toml` 檔，之後的預覽與套用步驟和內建的一樣。（檔案走「匯入設定」的預覽畫面，規則見上面的〈匯出與匯入設定〉與 [組態檔說明](config-file.md)。）

從檔案載入的預設組態，首頁會顯示「自訂」，它的服務在「服務」頁歸在「其他」群組。

檔案格式只讀取三個區段，其他區段（例如 `[timeouts]`）會被忽略、不會寫入設定，預覽畫面會列出被忽略的區段：

- `[preset]`：這組預設組態本身的資訊
- `[[cloud]]`：要加入的服務（可以有多個）
- `[route]`：潤飾與中翻英交給哪個服務

範例（位址請換成你自己的伺服器）：

```toml
[preset]
title = "辦公室伺服器"
id_prefix = "office-"                        # 本檔所有服務代號都要以它開頭
asr_choices = ["office-asr-fast", "office-asr-big"]   # 套用時讓使用者二選一
needs_key = ["office-asr-big"]               # 這些服務會詢問金鑰
# default_keys = { "office-asr-big" = "shared-lan-key" }   # 選填，見下方警告
detect_llm_model = true                      # 自動偵測文字模型名稱

[route]
polish = "office-llm"
translate = "office-llm"
cloud_fallback_to_local = true               # 服務失敗時退回地端

[[cloud]]
id = "office-asr-fast"
name = "辦公室 語音辨識（快）"
kind = "open_ai_compat"
base_url = "http://192.168.1.50:8001/v1"
asr_model = "my-fast-asr"

[[cloud]]
id = "office-asr-big"
name = "辦公室 語音辨識（準）"
kind = "open_ai_compat"
base_url = "http://192.168.1.50:8002/v1"
asr_model = "my-big-asr"
asr_timeout_ms = 8000                        # 選填，1000～60000

[[cloud]]
id = "office-llm"
name = "辦公室 文字模型"
kind = "open_ai_compat"
base_url = "http://192.168.1.50:8000/v1"
llm_model = "my-text-model"
```

欄位說明：

| 欄位 | 說明 |
|------|------|
| `[preset] title` | 顯示的名稱 |
| `id_prefix` | 服務代號的共同開頭，不可為空 |
| `asr_choices` | 套用時可選的語音辨識服務（至少一個，且該服務要有 `asr_model`） |
| `needs_key` | 需要金鑰的服務代號（金鑰在套用畫面輸入，存進系統金鑰庫） |
| `default_keys` | 選填。`{ "服務代號" = "金鑰" }`：使用者沒輸入、也沒有網址相同的舊金鑰時，套用會改存這把金鑰（代號必須在 `needs_key` 內；金鑰去頭尾空白後不可為空、不可含控制字元、最多 256 字元，否則整份拒絕）。畫面只會顯示「已內建預設金鑰，可不填」，不會顯示金鑰內容 |
| `detect_llm_model` | `true` 時向伺服器查模型清單，剛好一個就採用 |
| `[route] polish`／`translate` | 要用的文字模型服務（該服務要有 `llm_model`） |
| `[route] asr` | 忽略：語音辨識一律依你在套用畫面的選擇 |
| `[[cloud]]` | 服務；`kind` 一律是 `open_ai_compat`，必須有 `base_url`，其餘欄位（`name`、`asr_model`、`llm_model`、`asr_timeout_ms`）同 `config.toml` |

> **警告**：`default_keys` 的內容是明文，**拿到這個檔案的人都看得到**。只用在區網內大家共用的金鑰；個人或雲端服務的金鑰不要寫進檔案，也不要把這種檔案寄到外面或放上公開的地方。

驗證規則（任何一條不符，整個預設組態都不會套用，也不會改動你的設定）：

- 檔案要是 `.toml`，大小不超過 64 KB，且不能放在網路磁碟（`\\伺服器\...`）。
- `id_prefix` 不可為空，也不可以 `openai`、`gemini`、`claude`、`custom`、`local` 開頭（不分大小寫）；每個服務代號都要以 `id_prefix` 開頭、不可重複。
- 只能用 `open_ai_compat`（自訂相容端點）。
- 端點網址要正確；名稱最多 32 個字、不可與你現有的其他服務重複、不可用「local」；逾時要是 1000～60000 的整數毫秒。
- `asr_choices`、`needs_key`、`[route]` 指到的服務必須存在於檔內，並有所需的模型名稱；`default_keys` 的代號必須列在 `needs_key`。
- 預設組態只會新增或更新自己的服務（代號以 `id_prefix` 開頭）；若同一個代號在你現有設定裡是別種服務，會拒絕。

### 可能看到的錯誤訊息

| 訊息 | 原因與處理 |
|------|-----------|
| 只能在主視窗套用預設組態 | 請在 v2c 主視窗操作 |
| 找不到這個預設組態 | 內建預設組態名稱不存在，重新開啟 v2c 再試 |
| 請選擇 .toml 檔案 | 選到別種副檔名的檔案 |
| 無法讀取這個檔案 | 檔案不存在、沒有讀取權限、放在網路磁碟、選到的是資料夾，或檔案不是 UTF-8 文字 |
| 檔案太大（上限 64 KB） | 預設組態檔只需要幾 KB，確認選對檔案 |
| 預設組態檔格式不正確（缺少 [preset]、服務代號，或不是有效的 TOML） | 檢查 `[preset]`、`[[cloud]]` 的語法與必填欄位 |
| 服務代號必須以 id_prefix 開頭，且 id_prefix 不可為空或以 openai／gemini／claude／custom／local 開頭 | 改 `id_prefix` 或服務代號 |
| 預設組態的服務代號與你現有的其他類型服務重複，已拒絕以免覆蓋它 | 換一個 `id_prefix` |
| 預設組態內有重複的服務代號 | 每個 `[[cloud]]` 的 `id` 不可相同 |
| 預設組態只能使用「自訂相容端點」（open_ai_compat） | `kind` 改成 `open_ai_compat` |
| 預設組態內的語音辨識選項、需金鑰清單或用途指向不存在的服務，或缺少所需的模型名稱 | `asr_choices`、`needs_key`、`[route]` 的服務代號打錯，或該服務缺 `asr_model`／`llm_model` |
| 請選擇預設組態提供的語音辨識選項 | 套用畫面要選一個語音辨識 |
| 這個服務不需要金鑰 | 只有 `needs_key` 列出的服務可以輸入金鑰 |
| 金鑰格式不正確（請只貼上金鑰本身） | 金鑰中間夾了換行或其他控制字元（例如複製到兩行） |
| 預設組態內的端點網址不正確／內有服務沒有端點網址 | 檢查 `base_url` |
| 預設組態內的名稱與你現有的其他服務重複，請先修改或移除該服務 | 改預設組態的 `name`，或到「服務」頁改名／移除現有服務 |
| 預設組態內的名稱太長（最多 32 個字）／含有不允許的字元／使用了保留名稱「local」 | 修改 `name` |
| 預設組態內的語音辨識逾時不是整數毫秒／要在 1000～60000 毫秒之間 | 修改 `asr_timeout_ms` |
| 設定檔 config.toml 格式有誤，請先修正 | 你手動改過的 `config.toml` 有語法錯誤；修正後再套用 |
| 無法讀取設定檔／無法儲存設定檔，設定沒有變更 | 檔案被其他程式占用或沒有寫入權限；設定不會改變 |
| 無法存取金鑰庫，設定沒有變更 | 見〈疑難排解〉的「無法存取 Windows 認證管理員」（Linux 為 GNOME 鑰匙圈）；設定不會改變 |
