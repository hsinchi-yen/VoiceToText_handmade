# T1.13 自訂相容端點的別名

- 波次 / 前置：W7b ／ T1.7b 已合併（可與 T1.12 平行）
- 目標：使用者可以替「自訂相容端點」取別名（例如「區網 Qwen」）；沒填就顯示預設代號 `custom`、`custom-2`…。
- 先讀：`tasks/plan.md` 第 6.2 節（含「自訂相容端點的別名」）；`apps/desktop/src-tauri/src/commands/cloud.rs` 模組說明；`docs/cloud-setup.md`
- 允許修改：
  - `crates/v2c-core/src/config.rs`（**只**在 `CloudService` 新增 `name: Option<String>`，`#[serde(default, skip_serializing_if = "Option::is_none")]`；已獲你核准，2026-11-11）
  - `crates/v2c-core/src/**` 中因新欄位而必須補 `name: None` 的結構字面值（僅此類機械性修改）
  - `apps/desktop/src-tauri/src/commands/cloud.rs`、`apps/desktop/src-tauri/src/tray.rs`（若選單顯示服務名稱）、`apps/desktop/src-tauri/src/providers.rs`（僅補欄位）
  - `apps/desktop/ui/cloud-setup/**`、`apps/desktop/ui/settings/General.svelte`（僅限用途選單顯示名稱的部分；T1.12 也改此檔，改動要小）
  - `docs/cloud-setup.md`、`tasks/todo.md`
- 對外介面：`v2c_core::config::CloudService` 新增 `name`（已核准）；其餘 `v2c-core` 公開介面不得變更。
- 實作重點：
  - 只有 `kind = open_ai_compat` 可設名稱；其他種類送來的名稱忽略（存檔時不寫）。
  - 名稱去頭尾空白；空字串視為沒填（設定檔中移除 `name`）。允許中文；上限 32 個字元（以 Unicode 字元計），超過回傳錯誤碼，精靈顯示繁中訊息。
  - 名稱不可與其他服務的名稱或代號重複（不分大小寫），重複時回傳錯誤碼。
  - 顯示規則（一個共用函式）：有名稱 → 名稱；沒有 → `id`。套用於：精靈完成頁、服務清單、用途摘要（RouteSummary）、設定頁的用途下拉選單、系統列選單（若有列出服務）。
  - 精靈第 1 步選了「自訂」後（或測試連線前的頁面）多一個選填欄位「名稱（選填）」，placeholder 顯示將使用的預設代號；服務清單可「重新命名」（沿用編輯流程即可）。
  - `id` 的產生方式不變（`new_id`），改名不動 `id`、`[route]`、金鑰。
  - `config.toml` 用 `toml_edit` 寫入，保留使用者的註解與未知欄位。舊設定檔（沒有 `name`）照常讀取。
  - 日誌仍只記 `id`，不記名稱。
- 驗收：
  - 新增自訂端點時填「區網 Qwen」→ 清單、用途選單、摘要都顯示「區網 Qwen」；`config.toml` 有 `name = "區網 Qwen"`，`id` 仍是 `custom-N`。
  - 不填 → 顯示 `custom`（或 `custom-2`…）。
  - 改名後原本指到該服務的用途不變、金鑰仍可用。
  - 單元測試涵蓋：空白/空字串、超長、重複名稱、非相容端點忽略、舊設定檔讀取、toml_edit 寫入與移除 `name`。
  - `docs/cloud-setup.md` 說明如何取名與改名。
- 驗證指令：`cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --all --check`、`cd apps/desktop && npm run build`
- 🧑 需人工：安裝新版後替現有的 `custom`、`custom-2` 取名，確認各畫面顯示正確、潤飾/辨識照常運作。
- 合併：需你核准（`v2c-core` 介面變更＋🧑）
