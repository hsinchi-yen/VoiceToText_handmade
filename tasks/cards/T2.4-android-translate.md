# T2.4 Android 區網偵測、辨識路由、中翻英鍵

- 波次 / 前置：W10 ／ T2.3、T2.6
- 分派：實作 Sonnet（worktree，分支 `t2.4-android-route`）→ 測試 Haiku → 審查 Opus → 主 agent 決定（見 `README.md`〈分派流程〉）
- 目標：每句話依 `choose_asr` 選辨識來源（區網 TEA／Breeze、系統辨識、本機模型），失敗時照路由表退回；辨識來源小圖示（長按切換）；中翻英鍵。
- 先讀：`tasks/plan.md` 第 8.1、8.2 節；`v2cplan.md` 第 3 節 Android 各列
- 允許修改：`apps/android/app/src/main/java/**/{asr,recorder,translate,net}/**`、`apps/android/app/src/main/java/**/keyboard/**` 中來源小圖示與中翻英鍵、`apps/android/app/src/main/res/xml/network_security_config.xml`、`apps/android/app/src/main/AndroidManifest.xml`（只加 `networkSecurityConfig`、`ACCESS_NETWORK_STATE`、`INTERNET`）、對應的 `src/test/**`、`tasks/todo.md`
- 對外介面：使用 T2.3 的 FFI 與 T2.6 的 `LocalAsr`；不新增 FFI。
- 實作重點：
  - 區網偵測：對 TN、RD 的 TEA 端點各做 `GET /v1/models`，逾時 800 ms（常數），先回應者為目前區網；結果快取；`ConnectivityManager.NetworkCallback` 網路變更與鍵盤開啟時重測。偵測失敗的那句直接走本機。
  - 走區網或本機模型時用 `AudioRecord` 錄 16 kHz PCM；區網失敗時用同一段 PCM 交給本機模型（已下載時），否則提示重說。系統辨識失敗改本機模型時要使用者重說。
  - 來源小圖示：平常顯示目前來源；長按跳出 自動／TEA／Breeze／系統／本機；選擇存在 App 私有偏好檔。強制某來源但不可用時顯示原因，不靜默改用別的。第一次切到本機模型且未下載時，觸發 T2.6 的下載詢問。
  - 中翻英鍵：操作同麥克風（說中文 → 輸出英文），用目前區網的 Qwen；連不到區網時變灰，點了顯示「需要連上公司網路」。
  - `network_security_config`：只對 `10.20.30.23`、`10.88.95.2` 允許 cleartext。
  - 日誌只記來源、長度、延遲、錯誤碼。
- 驗收：單元測試涵蓋偵測快取與網路變更重測（假的 HTTP）、長按選單狀態；公司 Wi-Fi 下自動走 TEA；長按切 Breeze／系統／本機生效；關 Wi-Fi 自動改系統辨識；區網伺服器關閉時不卡頓；中翻英輸出英文；日誌沒有文字。
- 驗證指令：`cd apps/android && ./gradlew assembleDebug lint testDebugUnitTest`
- 🧑 需人工：在公司 Wi-Fi／VPN 與行動網路下實機測試（見 human-checklist）。
