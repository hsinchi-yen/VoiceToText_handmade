# T1.15 每個雲端服務各自的語音辨識逾時

- 波次 / 前置：W7c ／ 0.1.5 已合併（main `26bc30c` 之後）
- 目標：每個雲端服務可各自設定「語音辨識逾時」；沒填就用全域 `[timeouts] asr_cloud_ms`。精靈與服務清單提供建議值快選：Breeze-ASR-25 → 8000 ms、TEA-ASR → 8000 ms（暫定，之後依實測調整）。
- 背景（2026-11-11 你決定）：區網 Breeze-ASR-25 伺服器（`:8002`）實測每句 asr_ms 約 5.5～6.3 秒（連 2 秒短句也要 5.5 秒），6000 ms 會偶爾逾時並退回本機；全域值又會影響其他雲端服務，所以改成各服務各自設定。
- 先讀：`tasks/plan.md` 第 6.2 節（雲端服務、自訂相容端點的別名）；`crates/v2c-core/src/route.rs`（`build_cloud_asr`、`ProbeOptions`）；`apps/desktop/src-tauri/src/providers.rs`；`apps/desktop/src-tauri/src/commands/cloud.rs` 模組說明；`docs/lan-server-guide.md` 第 7 節附近的 `[timeouts]` 說明
- 允許修改：
  - `crates/v2c-core/src/config.rs`（**只**在 `CloudService` 新增 `asr_timeout_ms: Option<u64>`，`#[serde(default, skip_serializing_if = "Option::is_none")]`，以及一個取有效逾時的小方法，例如 `fn asr_timeout(&self, t: &TimeoutConfig) -> Duration`；已獲你核准，2026-11-11）
  - `crates/v2c-core/src/route.rs`（`ProbeOptions` 改用服務自己的逾時；不改其他公開函式簽名）
  - `crates/v2c-core/src/**`、`crates/v2c-platform/tests/linux_e2e_sim.rs` 中因新欄位而必須補 `asr_timeout_ms: None` 的結構字面值（僅此類機械性修改）
  - `apps/desktop/src-tauri/src/providers.rs`、`apps/desktop/src-tauri/src/commands/cloud.rs`、`apps/desktop/src-tauri/src/commands/settings.rs`、`apps/desktop/src-tauri/src/engine.rs`（後兩者僅補欄位）
  - `apps/desktop/ui/cloud-setup/**`
  - `docs/cloud-setup.md`、`docs/lan-server-guide.md`、`tasks/plan.md`（第 6.2 節加一段說明）、`tasks/todo.md`
- 對外介面：`v2c_core::config::CloudService` 新增 `asr_timeout_ms`、新增取有效逾時的方法（已核准）；其餘 `v2c-core` 公開介面不得變更。
- 實作重點：
  - 有效逾時 = 服務的 `asr_timeout_ms`，沒有就用 `[timeouts] asr_cloud_ms`。用在實際辨識（`providers.rs` 建 cloud ASR 時）與精靈／清單的「測試連線」。
  - 範圍 1000～60000 ms（整數）；超出回傳錯誤碼，精靈顯示繁中訊息。空白 = 沒填（存檔時移除欄位）。
  - 只對支援語音辨識的服務顯示這個欄位（相容端點且填了語音辨識模型，或 OpenAI／Gemini）。
  - 精靈中語音辨識那一步（填 `asr_model` 的地方）新增「語音辨識逾時（毫秒，選填）」欄位，placeholder 顯示目前全域值（例如「預設 8000」）；下方快選按鈕：「Breeze-ASR-25 建議 8000」「TEA-ASR 建議 8000」「用預設」。建議值放在 UI 的一個常數表裡（之後好調整），不寫死在多處。
  - 若 `asr_model` 名稱含 `breeze` 或 `tea`（不分大小寫）且欄位沒填，在欄位旁顯示對應的建議提示（不自動填入）。
  - 服務清單沿用編輯流程即可修改；清單上該服務若有自訂逾時，顯示「辨識逾時 8000 ms」。
  - 精靈原本「伺服器較慢時…可在設定檔 [timeouts] 放寬」的提示改成指向這個欄位。
  - `config.toml` 用 `toml_edit` 寫入，保留註解與未知欄位；舊設定檔（沒有此欄位）照常讀取。
  - 日誌：逾時錯誤已記 `ms`，維持只記 id、毫秒數，不記任何文字。
- 驗收：
  - 服務 A 設 8000、服務 B 不設、全域 5000 → A 用 8000、B 用 5000（單元測試）。
  - 精靈測試連線使用該服務的逾時（單元測試：mock 伺服器延遲 2 秒，服務逾時 3000 → 成功；1000 → 逾時）。
  - 超出範圍、非數字回傳錯誤碼；空白移除欄位；舊設定檔可讀；toml_edit 寫入與移除欄位保留註解。
  - 快選按鈕填入 8000；`npm run build` 無警告。
  - `docs/cloud-setup.md`、`docs/lan-server-guide.md` 說明此欄位與建議值（Breeze-ASR-25 實測 5.5～6.3 秒 → 建議 8000）。
- 驗證指令：`cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --all --check`、`cd apps/desktop && npm run build`
