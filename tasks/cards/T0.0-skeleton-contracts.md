# T0.0 開發環境、workspace 與核心介面

- 波次 / 前置：W0 ／ 無
- 目標：建立整個 workspace 骨架與 `v2c-core` 的公開介面，讓後續任務可以平行開發。
- 先讀：`tasks/plan.md` 第 1、2、3、4 節、第 5.1 節的 `[gpu]` 設定、第 6.1 節的 `[route]` 設定、第 7 節的隱私規則與 recorder；`v2cplan.md` 第 2～4 節
- 允許修改：根目錄 `Cargo.toml`、`.gitignore`、`rust-toolchain.toml`、`crates/**`、`tools/setup-dev.ps1`、`tests/fixtures/audio/README.md`、`tests/fixtures/audio/*.txt`、`tasks/todo.md`
- 對外介面（本任務定義，之後變更需你核准）：
  - `v2c-core`：`AudioClip`、`Mode`、`Lang`、`AsrContext`、`Transcript`、`AsrProvider`、`LlmProvider`、`Output`、`Timings`、`Pipeline`（簽名與 `todo!()`）、錯誤型別 `V2cError`、`config::Config`（完整欄位與預設值：`route`、`polish`、`gpu`、`history`、`mic_mode`、熱鍵門檻、App 規則）
  - `trigger.rs`、`inject_plan.rs`：事件/指令/Action 的型別定義（邏輯留給 T0.2、T0.3）
  - `v2c-platform`：`Hotkey` 與 `Injector` trait、`windows/`、`linux/` 空模組
  - `v2c-cli`：`clap` 子命令 `transcribe`、`bench`、`hotkey-test`、`inject-test`，每個一個檔案 `src/cmd/*.rs`，內容為 `todo!()`
- 實作重點：
  - 只寫介面、型別、預設值與文件註解，不寫業務邏輯。
  - `.gitignore` 排除 `target/`、`node_modules/`、`tests/fixtures/audio/*.wav`、`*.gguf`、`*.bin` 模型檔。
  - `tools/setup-dev.ps1`：winget 安裝 VS 2022 Build Tools（C++ 工作負載，Rust MSVC 與 whisper.cpp 必需）、Rust（MSVC）、LLVM（並設定 `LIBCLANG_PATH`）、Node.js LTS、CUDA Toolkit 12 以上（本機現有 CUDA 11.0 太舊）；每一步先檢查是否已安裝；腳本開頭列出將安裝的項目並要求確認。**agent 不執行此腳本。**
  - `tests/fixtures/audio/README.md`：10 段錄音的內容稿、格式（16 kHz mono WAV）、命名規則；每段一個期望文字 `.txt`。
- 驗收：`cargo build --workspace`、`cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings` 通過；config 預設值與 plan.md 一致（以單元測試比對）。
- 驗證指令：同上三個指令。
- 🧑 需人工：檢查並執行 `tools/setup-dev.ps1`；依 README 錄製 10 段音檔；審查介面。
- 合併：需你核准
