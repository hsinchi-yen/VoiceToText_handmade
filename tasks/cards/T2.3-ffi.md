# T2.3 Rust 核心接入 Android（uniffi）

- 波次 / 前置：W8 ／ T2.0；🧑 先完成 human-checklist Phase 2 的「Android Rust 工具」
- 分派：實作 Sonnet（worktree，分支 `t2.3-ffi`）→ 測試 Haiku → 審查 Opus → 主 agent 決定（新增 FFI 介面，合併需你核准）
- 目標：把 `v2c-core` 編譯給 Android 使用，提供繁體轉換、區網服務載入、遠端辨識、翻譯，以及辨識來源的路由決定。
- 先讀：`tasks/plan.md` 第 8 節（8.1 路由表、8.2 遠端與網路）；`crates/v2c-core/src/{asr,llm,route.rs,config.rs,postprocess/zh_tw.rs}`；`apps/desktop/src-tauri/presets/*.toml`
- 允許修改：`crates/v2c-ffi/**`、`apps/android/app/build.gradle.kts` 中 cargo-ndk 的建置任務、`apps/android/app/src/main/java/**/ffi/**`、`apps/android/app/src/main/assets/presets/**`（TN／RD `.toml` 原樣複製）、`tasks/todo.md`
- 對外介面（FFI，同步；內部自帶 tokio runtime；Kotlin 在 `Dispatchers.IO` 呼叫）：
  - `to_zh_tw(text) -> String`
  - `load_lan_services(tn_toml, rd_toml) -> LanServices`：用 `v2c-core` 的 `CloudService` 讀 `[[cloud]]`，用 `v2c-ffi` 內的小型結構讀 `[preset] default_keys`；只讀不寫
  - `transcribe_pcm(samples, rate, service_id) -> Result<String>`：交給 `v2c-core` 的相容端點 ASR，使用該服務的 `asr_timeout_ms`，Breeze 帶預設金鑰
  - `translate(text, service_id) -> Result<String>`：中翻英
  - `choose_asr(lan, system_available, local_model_ready, pick) -> AsrPlan`：純函式；`lan` 為 TN／RD／連不到；`pick` 為 自動／TEA／Breeze／系統／本機；`AsrPlan` 含主要來源、失敗時來源、是否需要重說、提示代碼
- 不做：輸入紀錄、Keystore、設定寫回（2026-11-12 你決定 Android 只有語音輸入與中翻英）。
- 實作重點：`reqwest` 使用 `rustls-tls`；`cargo-ndk` 編 `arm64-v8a`（另加 `x86_64` 給模擬器）；NDK 28.2 預設 16 KB 頁面對齊，仍要驗證；【實作前確認】uniffi 目前版本的設定方式。`choose_asr` 不做 I/O，區網偵測由 T2.4 在 Kotlin 端做。錯誤只回錯誤碼，不含辨識文字。不改 `v2c-core` 公開介面。
- 驗收：`cargo test -p v2c-ffi` 涵蓋 `tasks/plan.md` 第 8.1 節路由表每一列，以及「強制某來源但不可用時回提示、不靜默改用別的」；`load_lan_services` 對兩個內建檔與壞檔都有測試；APK 內含 `.so` 且 16 KB 對齊；Kotlin 呼叫 `to_zh_tw` 成功。
- 驗證指令：`cargo test -p v2c-ffi`；`cargo clippy --workspace --all-targets -- -D warnings`；`cargo fmt --all --check`；`cargo ndk -t arm64-v8a build -p v2c-ffi --release`；`cd apps/android && ./gradlew assembleDebug`；`zipalign -c -P 16 -v 4 <apk>`
