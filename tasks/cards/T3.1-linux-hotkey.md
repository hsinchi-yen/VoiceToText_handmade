# T3.1 Linux 能力偵測＋熱鍵

- 波次 / 前置：W12 ／ T3.0
- 目標：偵測 GNOME Wayland 的 portal 能力，選出熱鍵後端，把按鍵轉成 `trigger::Event`。
- 先讀：`tasks/plan.md` 第 3 節、第 9 節；`crates/v2c-core/src/trigger.rs`；`crates/v2c-platform/src/lib.rs`
- 允許修改：`crates/v2c-platform/Cargo.toml`（只加 `cfg(target_os = "linux")` 依賴）、`crates/v2c-platform/src/linux/{mod,caps,hotkey}.rs`、`crates/v2c-platform/src/lib.rs`（只加 Linux 用的錯誤變體）、`tasks/todo.md`
- 對外介面：實作既有 `Hotkey` trait；新增 `linux::caps::{LinuxCaps, probe()}`、`linux::hotkey::{HotkeyBackend, select_backend()}`；不改 `v2c-core`
- 實作重點：
  - `LinuxCaps` 純資料：session 類型、各 portal 是否存在與 `version`、evdev 是否可讀；`probe()` 用 D-Bus 讀屬性（只讀，不建立工作階段）。【實作前確認】`zbus`／`ashpd` 目前版本與 API。
  - `select_backend(&LinuxCaps)` 純函式：GlobalShortcuts → evdev → `Unavailable(原因)`。
  - 事件轉換純函式：evdev（KEY_RIGHTCTRL、KEY_LEFTSHIFT／RIGHTSHIFT、KEY_ESC、其他鍵；value 0/1/2，2=自動重複要忽略）→ `Event`；portal `Activated`／`Deactivated` → `KeyDown`／`KeyUp(Trigger)`。
  - evdev 開檔 `EACCES` → 明確錯誤「需要加入 input 群組」，不得自動提權。
- 驗收（mock）：轉換、後端選擇、自動重複、權限拒絕各有單元測試；把轉換結果餵進 `trigger::Machine` 跑完按住說話、雙擊免持、Ctrl+C 取消、Shift 翻譯、Esc 取消。
- 驗收（本機真實、唯讀）：`probe()` 在本機回報 GNOME 42 沒有 GlobalShortcuts、RemoteDesktop v1；開 `/dev/input/event*` 得到權限錯誤（`#[ignore]` 測試，手動執行）。
- 驗證指令：`cargo test -p v2c-platform`；`cargo test -p v2c-platform -- --ignored linux_real`；`cargo clippy -p v2c-platform --all-targets -- -D warnings`；`cargo fmt --all --check`
- 🧑 需人工：加入 `input` 群組後實機按鍵；在 GNOME ≥ 48 的機器測 GlobalShortcuts。
