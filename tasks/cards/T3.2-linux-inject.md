# T3.2 Linux 剪貼簿注入

- 波次 / 前置：W13 ／ T3.1（共用 `linux/mod.rs` 與 `LinuxCaps`）
- 目標：在 GNOME Wayland 執行 `inject_plan::Action`，一律以剪貼簿＋Ctrl+V 輸出，能力不足時明確失敗並退回「只複製」。
- 先讀：`tasks/plan.md` 第 4 節、第 9 節；`crates/v2c-core/src/inject_plan.rs`；`crates/v2c-platform/src/windows/inject.rs`（流程參考）
- 允許修改：`crates/v2c-platform/Cargo.toml`（Linux 依賴）、`crates/v2c-platform/src/linux/{mod,inject,clipboard,keys}.rs`、`crates/v2c-platform/src/lib.rs`（只加 `InjectError` 變體，如 `PermissionDenied`、`Unsupported`）、`tasks/todo.md`
- 對外介面：實作既有 `Injector` trait；新增 `ClipboardBackend`、`KeyBackend` trait 與 `LinuxInjector<C, K>`；不改 `v2c-core`
- 實作重點：
  - `Text` 與 `Paste` 都轉成貼上（Wayland 下中文無法逐字送 keysym）；`NewLine(Enter|ShiftEnter)` 以 keycode 送。
  - 流程：等修飾鍵放開（最多 500 ms）→ 備份剪貼簿 → 設定文字 → Ctrl+V → 等待（設定值）→ 剪貼簿仍是我們設的才還原。
  - 真實後端：RemoteDesktop portal `NotifyKeyboardKeycode`（Ctrl=29、V=47、Shift=42、Enter=28）；Clipboard portal（GNOME ≥ 45）。使用者取消對話框（portal response 1）→ `PermissionDenied`；沒有 portal → `Unsupported`。建立工作階段會跳出對話框，**測試不可自動觸發**。【實作前確認】ashpd `remote_desktop`／`clipboard` API。
  - 部分失敗時一定送出放開按鍵（不可留下按住的 Ctrl）。
- 驗收（mock）：mock 後端記錄呼叫序列；涵蓋多行、Shift+Enter、修飾鍵逾時、權限拒絕、剪貼簿設定失敗、Ctrl+V 送一半失敗後仍放開 Ctrl、還原與「被別人改過不還原」。
- 驗收（本機）：本機 GNOME 42 由能力偵測得到 `Unsupported`（剪貼簿），流程退回且錯誤可讀。
- 驗證指令：`cargo test -p v2c-platform`；`cargo clippy -p v2c-platform --all-targets -- -D warnings`；`cargo fmt --all --check`
- 🧑 需人工：在 GNOME ≥ 45 實機測貼上到 gedit／Firefox／終端機；RemoteDesktop 同意對話框按「取消」的提示。
- 合併：需你核准（含 🧑）
