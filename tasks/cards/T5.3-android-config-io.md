# T5.3 Android 組態檔匯出／匯入（FFI＋APK）

- 波次 / 前置：W23 ／ T5.1、T2.8
- 分派：實作 Sonnet（worktree，分支 `t5.3-android-config-io`）→ 測試 Haiku → 審查 Opus → 主 agent 決定（見 `README.md`〈分派流程〉）
- 目標：手機設定頁的「雲端服務」區塊可以匯入桌面版或手寫的組態檔，也能匯出手機上的雲端設定；只套用手機用得到的部分。
- 先讀：`tasks/plan.md` 第 14 節、第 8.1、8.3 節；`docs/config-file.md`；`crates/v2c-core/src/portable.rs`；`crates/v2c-ffi/{ANDROID.md,src/lib.rs,src/services.rs}`；T2.8 合併後的 `apps/android/app/src/main/java/app/v2c/ime/cloud/**` 與 `SetupActivity.kt`
- 允許修改：`crates/v2c-ffi/**`、`apps/android/app/src/main/java/app/v2c/ime/{SetupActivity.kt,cloud/**}`、`apps/android/app/src/main/res/values*/strings.xml`、對應的 `src/test/**`、`docs/android-install.md`（「串接雲端服務」一節加匯入／匯出，連到 `docs/config-file.md`）、`tasks/todo.md`、`tasks/human-checklist.md`
- 實作重點：
  - FFI：`parse_config_file(text) -> ConfigFilePreview`（可套用的服務、跳過的服務與原因代碼、忽略的區段、需要金鑰的服務、錯誤碼＋行號）、`export_config_file(...) -> String`。邏輯全部在 `v2c_core::portable`，FFI 只做型別轉換。
  - 手機套用規則照第 14.3 節「Android」：官方服務與 HTTPS 相容端點才匯入；與內建 TN／RD 同 id 的標示「已內建」並跳過；HTTP 端點跳過；`route.asr`／`route.translate` 對應到「語音辨識」／「中翻英」用途（各最多一個）；`route.polish` 與詞庫忽略並在預覽列出。
  - 合併：依 id 新增或更新；端點改變時刪掉該服務的舊金鑰；其他服務與金鑰不動；套用後呼叫 `set_cloud_services`，下一句生效。
  - 檔案：SAF `ACTION_OPEN_DOCUMENT`／`ACTION_CREATE_DOCUMENT`，不加儲存權限；檔案大小上限 256 KiB。
  - 金鑰不匯出；匯入時依 `needs_key` 提示貼金鑰（只顯示末 4 碼，沿用 T2.8 的 Keystore 存法）。
  - 日誌只記：服務數、跳過數、錯誤碼、耗時。
- 驗收：
  - Rust：用 `tests/fixtures/config/` 跑 FFI 預覽；桌面匯出的檔案（含 HTTP 區網服務與詞庫）在手機預覽中正確分類。
  - Kotlin 單元測試：合併規則、用途對應、端點改變刪金鑰、匯出內容不含金鑰（假 Keystore）。
  - 現有 Android 單元測試照常通過。
- 驗證指令：`cargo test -p v2c-ffi`；`cargo clippy -p v2c-ffi --all-targets -- -D warnings`；`cargo fmt --all --check`；`cd apps/android && ./gradlew assembleDebug lint testDebugUnitTest --rerun-tasks`
- 🧑 需人工：把 Windows 匯出的檔案傳到手機匯入，確認 Gemini／OpenAI 服務與用途出現、貼金鑰後能說話；手機匯出的檔案在 Windows 匯入成功。
