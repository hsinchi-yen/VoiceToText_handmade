## 分派流程（2026-11-12 你決定，Phase 2 起）

| 角色 | 模型 | 拿到什麼 | 做什麼 |
|------|------|----------|--------|
| 主 agent（分派） | Opus | 全部文件 | 挑選前置已合併的卡、分派、彙整結果、決定下一步；同時最多 3 個實作＋1 個審查 |
| 實作 | Sonnet | 卡片路徑＋卡片「先讀」的章節 | 在自己的 worktree 與分支（`t<id>-<slug>`）實作、commit；回報改了什麼與驗證結果 |
| 測試 | Haiku | 分支名稱＋卡片的「驗證指令」與「驗收」 | 照指令執行，回報每條指令的通過或失敗與錯誤摘要；不修改任何檔案 |
| 審查 | Opus | 只有 diff 與卡片（不給實作者的摘要） | 檢查驗收條件、範圍（只動允許路徑）、不記錄辨識文字、測試是否足夠；回報「通過」或「退回＋具體問題」 |

每張卡的步驟：

1. 主 agent 分派實作（Sonnet）。
2. 實作完成 → 測試（Haiku）。失敗：主 agent 把失敗摘要交回同一個實作 agent 修正，再測。
3. 測試通過 → 審查（Opus）。退回：交回實作 agent 修正，回到步驟 2。
4. 審查通過 → 主 agent 決定：
   - 沒有 🧑、也沒動 `v2c-core` 公開介面 → 合併進 `main`，分派下一張卡。
   - 有 🧑 或介面變更 → 停下，向你回報並等你核准後才合併（`AGENTS.md` 規則）。
5. 同一張卡退回 3 次仍不通過 → 停下向你回報。

## 卡片格式

```
# T<id> <標題>
- 波次 / 前置：
- 分派：實作 Sonnet → 測試 Haiku → 審查 Opus → 主 agent 決定
- 目標：一句話
- 先讀：文件章節連結（不複製內容）
- 允許修改：路徑清單（以外的檔案不准動）
- 對外介面：本任務提供或依賴的型別/函式；不得變更 v2c-core 公開介面（要改先停下請示）
- 實作重點：
- 驗收：
- 驗證指令：
- 🧑 需人工：
- 合併：自動 ／ 需你核准
```
